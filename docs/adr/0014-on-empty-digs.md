# 撬底：出空即撬底，赢墩不再是前提

本仓库的旧 4.8 把撬底绑定在“本墩赢家”上：只有赢下本墩且打空手牌、又无牌可补的那家才收分结束本局（RULES_REVISION 2，见 [ADR-0007](./0007-family-comparison.md) 之前的 RULES.md §4.8/§4.9、“留局 0 张”）。用户 2026-09-26 裁定这是错的：**打空手牌（“出空”）本身就该撬底，赢不赢这一墩无关**。旧规则把“必须赢墩”当作触发条件，导致非赢家出空后只能留局干等，直到某个赢家碰巧出空——这既不符合“出空结束本局”的直觉，也让终局依赖无关的赢墩。本 ADR 固定新语义，供引擎/回放/定级共同引用。

## 决定

1. **立即结束（主路径）**：某家打出自己的最后一张牌、且**此时**底牌堆为空 ⇒ 本局立即结束。对手没有任何应牌权（不进入 `_advance`，不产生后续 `step`）。出空者撬底，收走所有尚未被收走的分牌：本墩弃牌 + 其他家手牌中的分牌；已入账分数不动，不翻倍。`StepResult` 为 `trick_over=True, dug=True, done=True, winner=出空者, points_taken=本墩分+扫到的手牌分, refilled=()`。
2. **前提不变**：底牌堆必须为空。出空时底牌堆还有牌 ⇒ 不撬底、不结束，照常继续（本墩结束照常补牌）。牌堆是否为空以出牌那一刻为准。
3. **优先级**：**最先出空者撬底**。主路径下立即结束，实际就是该次出空者；补牌阶段的角落是：某家在本墩中途出空（当时牌堆非空），本墩结束补牌时牌堆恰被发空、该家（或数家）补不上牌，则由其中**最早出空**的那家撬底。引擎在 `GameState.empty_order` 中按出空先后记录当前空手的座位；补到牌的座位从该序列移除。N 家存在多个空手家时取序列首个。

撬底的分牌口径（4.8 的算术）完全沿用：只扫尚未被收走的**分牌**，非分牌留在原手；本墩的 `trick_points` 归撬底者（不再先记给赢家）；银行里的 `scores` 不动。撬底者自己不可能是本墩赢家也没关系。

## 实现

- `src/seven523/game.py`：`GameState` 新增引擎内部字段 `empty_order: tuple[int, ...]`（构造/相等/`replace` 自动一致；`Deal`/`restore` 开局为空）。`step` 在打空手牌时把该座位追加进序列，并在“空手 + 底牌堆空”时立即调用 `_end_trick(..., immediate_digger=seat)`；`_end_trick` 补牌后移除已补牌的座位，再由 `empty_order[0]` 决定补牌角落的撬底者。`StepResult.winner` 统一表示**收走 `points_taken` 的座位**：普通墩是赢家，撬底墩是撬底者。
- **投影不变**：`empty_order` 既进 `View` 也不进观测编码；`observation_dim`、动作目录、`MultiDiscrete([134, 4])` 与 v5 布局逐位不变（ADR-0002/0004/0008）。`Game.view` 不新增字段，测试断言 `View` 与观测在 `empty_order` 变化下逐位相等。
- `src/seven523/rules.py`：`RULES_REVISION` 2 → 3，`rules_id` 由 `fbd43015d526ee72` 变为 `2e36dbea44893696`（该旧 id 从此是历史值）。
- `src/seven523/trace.py`：`TRACE_VERSION` 2 → 3，`build_trace` 在 `rules` 段记录 `revision=RULES_REVISION`；`play.replay_trace` 拒绝任何 `version < 3` 或 `rules.revision != RULES_REVISION` 的记录，绝不静默回放旧终局。
- RULES.md §4.8/§4.9、§6、§7 增 R-Q13；CONTEXT.md 的「撬底」词条同步；重训/重测排期见 `docs/plans.md` T17。

## 考虑过的替代

- **保留“必须赢墩”**：旧规则已由用户裁定为对规则意图的误解，继续保留就是保留错误终局。
- **允许对手应牌后再结算**：出牌后若有人能压，出空者未必赢；但“立即结束、无人可应”正是用户裁定的语义，允许应牌会把终局重新绑回赢墩。
- **出空即结束但由本墩赢家撬底**：出空者与赢家不同时会让分牌归属出乎直觉，且“最先出空者优先”直接给出唯一归属。
- **补牌阶段让每个空手家各扫一次/按赢家优先**：与“最先出空者撬底”的优先级裁定冲突，且多次扫分不守恒。
- **在 `View`/观测里暴露出空顺序**：违反 ADR-0002 单一投影接缝，且会改变观测布局；该信息在手牌数里已经公开，无需新增维度。

## 后果

- 规则语义变更 ⇒ **所有旧资产作废**：`traces/study`、`traces/pool10` 及一切 v2 轨迹、在该规则下训练的 checkpoint、manifest 强度表、`prior.json` 标定，都必须在新规则下重测/重训后才能与未来数字混比（`rules_id` 门禁与回放拒绝都是刻意的 fail-loud，不是回归）。
- 现有 checkpoint 是在旧终局规则下练出来的，强度未知；在重训并重测前，placement/`7g523-elo` 会拒绝旧 manifest（`rules_id` 不匹配），真人定级暂停。
- 旧规则下的“留局 0 张、干等到赢家撬底”状态不再存在：合法对局中，空手 + 底牌堆空只可能出现在终局（立即结束或补牌阶段结束）那一刻。
- `tests/test_fit_trace_prior.py` 中以 `verify=True` 读取旧 `traces/study` 的三个数据回归在新规则下会拒绝旧 trace，暂以引用 T17 的 skipif 标记，套件保持全绿；拒绝本身仍由 `tests/test_trace.py`/`tests/test_placement.py` 覆盖。T17 重测数据落盘（manifest 换新 `rules_id`）后同一批测试自动恢复运行。
