# 隐藏信息只穿过一个投影接缝

引擎是**全知**的（它必须知道底牌堆顺序与他家手牌才能推进流程），但训练与自博弈的 agent 不能看到隐藏信息。选择：不引入 `PlayerView`/`GameState` 双类型，也不做不透明 `Table`，而是让**唯一**的 agent 信息通道是 `Game.view(state, seat) -> View`；`View` 只装公开字段加自己的手牌。测试与回放直接读 `GameState`（全知），因此这条接缝天然有两个 adapter（生产投影 / 测试·回放全知）。

## 考虑过的替代

- 靠纪律：把全知 `State` 交给调用者、文档约定别乱读（太弱）。
- 双类型 + 不透明 session：类型边界上无法泄露，但要多养一套类型与端口。
- 只靠差分测试：不加类型约束，用“两份仅隐藏字段不同的状态必须产出相同 obs/mask”兜底。

## 后果

选投影接缝 + 差分泄漏测试（`tests/test_game.py::test_view_does_not_leak`）双保险；代价是 `GameState` 仍在 in-repo 代码里公开，泄露只能由测试而非编译器拦截。
